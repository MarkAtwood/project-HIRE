# Governance

**One maintainer decides.** That is the whole of it, and this file exists to say
so rather than to describe a committee that does not exist. Inventing one would
read worse to anyone evaluating the project than a single-maintainer project
that is honest about being one.

## How decisions are made

The maintainer in [MAINTAINERS.md](MAINTAINERS.md) has final say on design,
scope and releases. Anyone may open an issue or a pull request; there is no
sponsorship requirement and no CLA beyond the Developer Certificate of Origin
described in [CONTRIBUTING.md](CONTRIBUTING.md).

Decisions with lasting consequence are recorded where the work happens rather
than in meeting minutes: in the commit message that made the change, in the
issue tracker, and in a comment next to the code the decision constrains. A
decision that is not written down anywhere has not been made.

## How this changes

Adding a second maintainer is the next step and is deliberately not automatic:
it takes a sustained contribution history and the current maintainer's
agreement. When there are two, this file gets a tie-break rule, because two
maintainers without one is worse than one maintainer.

If the project is donated to SPIFFE, its governance replaces this file
entirely -- the SPIFFE Steering Committee holds final authority over technical
direction, governance and contribution policy for projects under it.
[UPSTREAM.md](UPSTREAM.md) has the plan and what it would cost.
